# JingKong v1.0.2

## 中文

修复有线投屏「一键安装全部驱动」反复出现、装完卡在「等待设备重新连接…」、以及重连后 iPhone 从系统中消失的问题。

**根因**：采集过滤器必须靠设备重启才能绑定生效，但 Apple Mobile Device Service 在安装期间正占用同一个 USB 父设备的 usbmux 接口。Windows 因此否决了设备移除（内核 PnP 事件 225），重启没有完成，`libusb0` 始终未加载。驱动管理器却仍判定「安装成功」，提示用户拔插；拔插时半应用的过滤链会让用户模式驱动宿主崩溃（事件 10116），设备随之离线。下次启动预检读不到已加载的过滤器，于是再次弹出安装页面——形成循环。

**修复**：

- 安装/卸载采集过滤器前先停止 Apple Mobile Device Service，操作完成后自动恢复。设备重启不再被否决，过滤器一次装好即生效。
- 过滤器服务已运行时不再要求拔插设备，直接跳过重连引导。这也消除了那个关不掉的「等待设备重新连接…」等待窗口。

## English

Fixes the wired-mirroring loop where "install all drivers" kept reappearing, the installer stalled on "waiting for the device to reconnect", and the iPhone dropped off the system after reconnecting.

**Root cause**: The capture filter only binds after the device restarts, but Apple Mobile Device Service holds the usbmux interface on the same USB parent during the install. Windows therefore vetoed the removal (Kernel-PnP event 225), the restart never finished, and `libusb0` was never loaded. The driver manager still reported success and asked for a replug; the half-applied filter chain then crashed the user-mode driver host (event 10116) and took the device offline. The next launch found no loaded filter and prompted again — a loop.

**Fix**:

- Stop Apple Mobile Device Service before installing or removing the capture filter and restore it afterwards, so the parent restart is never vetoed and the filter takes effect on the first attempt.
- Do not ask for a replug when the filter service is already running, which also removes the unclosable "waiting for the device" screen.
